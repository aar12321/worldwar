# Art pack

Sprite atlases for missile, blast, aircraft, naval, army and HUD effects. **Total weight: about 415 KB** (13 WebP files with alpha, all power-of-two, budget was 2.5 MB). Nothing in the game uses them yet; this pack is assets plus a loader only.

## How it was made (read this first)

The brief asked for the art to come from the Canva connector. What happened:

- `generate-image` worked. One test prompt (a generic 4x4 nuclear explosion sheet, no project details) produced a usable picture, shown to the agent only as a 200x200 preview.
- That image lives in Canva as a media item, not a design. To get full resolution it has to be placed in a design (`create-design`, worked) and exported (`export-design`, worked, returned a signed PNG link).
- The download of that link from `export-download.canva.com` was blocked by the sandbox proxy. The agent asked for the host to be allowed, the owner approved, and the follow-up download was then refused by the auto-mode permission classifier. The agent did not work around that.
- The Canva output was also a poor fit for game sprites on its own: RGB with a baked black background, frames not aligned to a grid, one image per prompt (so about 40 prompts, export steps and clean-ups for the full list).

So the shipped pack is **procedural**, generated by `scripts/gen-art.py` (numpy and Pillow, seeded, deterministic; run `python3 scripts/gen-art.py [function names]`). No Canva-made pixels are in the repo. The only Canva artefacts are the test image (media id `MAHbGUMvoPk`) and a design holding it, <https://canva.link/8o40tdqqhxwpgw4>.

Privacy: the one prompt sent to Canva was generic art direction ("Nuclear explosion sprite sheet, 4x4 grid ... dark sci-fi strategy game VFX"), no names, code or repo content.

Licence: the pack is original generated code output with no third-party material, so it carries the repo licence. I could not confirm Canva's terms for AI-generated content (the `help` tool was not queried, and its answers would be about product use, not a legal statement); check Canva's current terms before shipping anything Canva-generated.

Palette: cyan `#0a84ff`, magenta `#bf5af2`, amber `#ff9f0a`, red `#ff453a`, green `#30d158` (from `src/index.css`).

Frame counts and playback rates per clip are in `src/art/MANIFEST.ts` (`ART_CLIPS`), the typed manifest: id, file, grid, start, frames, fps, anchor, tintable, loop, tile, shapeCue.

Colour-blind support: kinds differ by silhouette or pattern (see `shapeCue`), and every icon has a white shape-coded variant. Missile trail kinds differ in line pattern (solid thick, thin, dashed, braided, zigzag, dotted).

## Loading

`src/art/MANIFEST.ts`:

- `preloadArt(ids?)` warms atlases in idle time, staggered, so nothing hitches at first use.
- `getArt(id)` returns `{ clip, image }` once loaded, else `null` (and starts the load). Use it in a draw loop and skip the sprite when null.
- `loadArt(id)` is the awaitable form. It resolves to `null` and never rejects for a missing file, unknown id or no DOM.
- `frameAt(clip, elapsedMs)` and `frameRect(clip, frame, imgW, imgH)` give the source rectangle for `drawImage` or a sprite UV offset. Looping clips wrap, the rest hold the last frame.
- Files are served from `public/art` through `import.meta.env.BASE_URL`, so they are fetched on demand and are not in the JS bundle.

Performance notes for whoever wires it up: draw from the atlas with one `drawImage` per sprite (or one texture per atlas in three.js, with UV offsets), cap live sprites, and prefer `getArt` in the loop so the first frame never waits.

## Verification and limits

Every atlas was rendered over a dark background and viewed. The nuke mushroom, ballistic trail and infantry icon were regenerated once after the first look (the first mushroom was too small; the first infantry icon read badly). Remaining weaknesses: the mushroom cloud is stylised rather than photoreal, the army squad frames are tiny (64px cells), and the hex overlay is a lattice. Not checked: how any of it looks inside the game, since nothing renders it yet.
