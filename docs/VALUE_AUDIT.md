# Value audit

A sweep to check that every value, option, setting and number the game shows or tunes does something, and that what the screens say is what the engine does. UI layout files were left alone (another pass is changing them).

How it was done: throwaway scripts walked every key of every table in `src/data` and looked for a read in the engine, the AI or the screens (`NAME.key`, `.key`, destructuring); a second walk went two levels deep; a third listed every export that nothing imports; a fourth listed every `types.ts` field that production code barely touches. Table-wide checks (tiers, technology costs and requirements, aircraft requirements, program enact costs, non-finite numbers) ran as throwaway tests. Descriptions that quote numbers (laws, buildings, technologies, projects, Help terms, border and nuclear text, loan limits, faction costs) were compared with the constants the engine uses. `src/engine/__tests__/valueAudit.test.ts` keeps the useful checks in the suite, including a guard that fails when a rules constant in `src/data` is defined but never read.

## Findings

| Item | Finding | Action |
|---|---|---|
| Social programs, campaigns, projects: `famine`, `epidemic`, `order` | Shares of a trouble that goes away, summed with no ceiling. Every program, project and campaign together reach about 190% on famine and 110% on plague, so `1 - famine` went negative and hunger became a stability bonus (about +24). | Fixed. `SOCIAL_RULES.shareCap` (0.9) caps the three sums in `societyEffects`. Test in `valueAudit.test.ts`. No golden moved. |
| `BORDER.closedCover` | Described in the data as the cover a closed border adds; the engine had a literal `0.25`. A test read the constant, the game did not. | Fixed. `borderCover` reads the constant. |
| `COALITION.memberRest` | Defined, read nowhere. The real rest is `COALITION.rest`/`restTotal`. | Removed. |
| `FRONTIER.strikeKm`, `strikeLine`, `strikeLineMax`, `strikeFactoryTurns` | Old copies of the hypersonic numbers, which live in `MISSILES.hypersonic` (the engine reads those). Changing them did nothing. | Removed. `strikeMoney` (read) kept, comment points to `MISSILES`. |
| `EMPIRE.settleRegions`, `WAR.overextendFree`, `WAR.overextendPenalty` | Described a stability cost for holding many unsettled countries. The real mechanism is the administration load (`EMPIRE_RULES.over*`) and the unsettled floor. | Removed. |
| `COSTS.declareWar` (25) | A war with no reason costs `JUSTIFY.noReasonCost` (60), with one `COSTS.declareWarWithCasusBelli`. The 25 was never charged or shown. | Removed. |
| `DIFFICULTY.*.attackRatio` | A per-difficulty bot attack threshold the AI never read (bots decide from `warDeclarePowerRatio` and the War Room forecast). `docs/STRATEGY.md` still mentions it historically. | Removed from type and tables. |
| `LIVE.missileDays`, `LIVE.speeds` | Missile flight time is `MISSILES[kind].days`; the speed buttons use their own list matching `settings.liveSpeed`. A test asserted the dead constant. | Removed. Test now reads `MISSILES.hypersonic.days`. |
| `SOCIAL_RULES.perMonth` | "A policy can be changed once a month" was written as a number nothing read (the rule is enforced by the order check). | Removed. |
| `OUTPOST.upkeep` | Outpost upkeep is computed from what was invested (`spaceEffects`), not from this number. | Removed. |
| `DIPLOMACY.loan.max`, `maxMonths` | Superseded by the tier's `loanMax`/`loanMonths` (the UI and the order check use the tier). | Removed. |
| `MARKET.*.short` | Duplicate of `name`, never shown. | Removed. |
| `BUDGET`, `BUDGET_KEYS`, `EVEN_BUDGET`, `budgetEffects`, `buildDiscount`, `BudgetSpec` | The four-slice budget was replaced by spending levels; only the old-save migration (`spendingFromBudget`) remains. Nothing called these. | Removed. `BUDGET_LIMITS` kept (read by the migration). |
| `people.focusSince` | A saved-state field written when the school focus changed, never read (specialization restarts from 0 and builds over `specializationMonths`). | Removed from type, start state and order. Goldens re-pinned (see below). |
| Unused functions | `reserveOf`, `alliedWarTargets`, `asTraining`, `devState`, `armiesOf`, `inTheField`, `writeOffBonds` (the default code in `business.ts` does the write-off), `fundingCost`, `deploymentOf`, `factoryCount`, `sumUnits`, `labSlots`, `hasDiscovery`, `padAllows`, `ROCKET_ORDER`, `loyaltyOf`, `systemLevel`, `MATERIALS_LIST`, `localCount`. | Removed, with the imports they left unused. |
| Barracks line in `BUILDING_SPECS` | Said "+1 training slot and +0.75 defenders per level". The engine also adds +0.5 Defense Line per level and faster healing. | Fixed (text). |
| Building lines (factory +6, farm +3, university +2.5, port +3, civic +0.6/+0.3) | Match `ECON` and the economy. | Kept. Test pins the first four to `ECON`. |
| Law, technology, project and local-project descriptions | Every percent in a law or technology text matches its modifiers (checked by script); first-seven project effects match the `scaleFactor`/`scaleBonus` calls in `economy`, `people`, `systems`, `empire`; local project lines are generated from `yields`. | Kept, no change needed. |
| Help text and README numbers | Checked against constants: food shortage 30%, settling 40% to 100% over 6 months, 3 wars, bond default after 3 months with half written off and a 2-year lockout, 17 projects, 22 programs in 5 groups, tiers at 4/10/25/60, rush 4 months for 2, missile program capacity 5/10/18, nuclear (4 warheads, 4 months, 5 days, two thirds of the people, a quarter stopped by a level 3 shield), garrison +35% and half strength elsewhere, closing a border 3 influence, faction costs 15/10/60, puppet loyalty bands 15/25/35/60/75, 7000 km air reach, 16 aircraft developments with slots 1 or 2. | All match. |
| Order costs: preview vs charge | `orderCost` is the single source for the preview and the charge (`resolveTurn`, `applyOrderNow`); the only extra charges are research points taken inside the applying function for orders whose `tp` the generic charge does not take (research, aircraft development, missile program, warhead, space labs and nodes, programs). None is charged twice (`actions.test.ts` checks each charged resource moves once). | Kept. |
| Settings | `reducedMotion`, `fxSpeed`, `battleScenes`, `seenHelp`, `monthlyReport`, `showGuide`, `pauseOnBattles`, `liveReport`, `liveSpeed` and every UI preference are read by the game. | Kept. |
| Level tables | Empire tiers never lose a right as they grow (trust is lower-is-better; the World Council share falls from 2/3 to 1/2 on purpose); technology costs rise with tier and never require a later tier; program enact costs rise by level; aircraft requirements never point to a later tier; no non-finite number anywhere in `src/data`. | Kept. Tests added. |
| Dominance | Drone swarms beat every unit on attack per money and upkeep. By design: no soldiers, no defense, and shields, fighters and Cyber Command counter them. "Write it off" after an industrial accident is worse than rebuilding unless the treasury is empty. No government form dominates the others (democracy gains research and growth but pays more for taxes and war). | Kept, no change. |
| `CoalitionPlan.formed`, `FactionInvite`, other state fields | Read only by tests or only for display ordering. | Kept (tests use `formed` to check the warning time). |
| `LIBERATE_TEXT.term`, `short`, `hint`, `none` | Peace table words for "set a puppet free". The engine, AI and refusal text work, but no screen offers the term to a human player, so these words are unused. | Kept and flagged: needs a control in the peace table (a UI task, outside this pass). Guard test allow-lists them. |
| Unused UI exports | `GridIcon`, `KeyboardIcon`, `puppetSummary`, `useMedia`, `settingsFor`, `ConfirmButton`, `InfoTip`, `Ticker`, `Announce` have no importer. | Kept: UI files are being changed in parallel. Listed for the next UI pass. |
| Exports used only inside their own file or only by tests | About 150 type and helper exports (`UNUSED local`, `TESTONLY`). Harmless. | Kept. |

## Goldens

`turnGolden.test.ts` was re-pinned for the three state hashes (Normal-bot world, Hard-bot world, small war), and the posture-free twelve-month hash in `deployment.test.ts` (`101a385ac39465`) because `people.focusSince` left every nation's saved people. The battle log hash did not move. Proof: on the code just before the removal, hashing the same states with that one key skipped gave exactly the new pins (`1b61219982f9c1`, `ee22ac4b8fdef`, `14c280eef9180f`). Every other change in this audit moved no golden.
